# Правила работы

## Источники требований

- `README.md` — бизнес-правила и HTTP-контракт исходной версии.
- `docs/architecture.md` — обязательные слои, структура, модули и сборка.
- `docs/acceptance.md` — сценарии проверки.
- Образец дизайна — фиксированная ревизия chat-ops, указанная в архитектуре.

## Реализация

- Перед изменением проверяй ветку, рабочее дерево, соседний код и тесты.
- Сохраняй структуру Api/App/Infra, Core внутри App,
  группировку Features и регистрации в Module.cs.
- Общие адаптеры регистрируй только на уровне модуля Api:
  `Program.cs → Api/Module.cs:AddAdapters → Infra/SharedAdapters/Module.cs:AddSharedAdapters`.
  Не вызывай `AddSharedAdapters` из модулей Features или Workers.
- Все воркеры размещай в `Api/Workers/<WorkerName>/`, включая одноразовые.
  Рядом в `Module.cs` регистрируй воркер и его собственные зависимости;
  `Api/Workers/Module.cs` объединяет регистрации в `AddWorkers`.
  Общие адаптеры подключаются через `AddAdapters`, подключение БД — через
  `AddIntegrations`, HTTP-настройки — через `ConfigureApi`.
- Не заменяй принятый дизайн другими слоями, MediatR, generic repository,
  EF Core или глобальным сканированием регистраций.
- Используй .NET 10, централизованные версии пакетов и отдельные props тестов.
- Бизнес-правила не переносятся в HTTP-обработчик, SQL-адаптер или фоновый таймер.
- Доменные значения с инвариантами оформляй как records с проверками.
  Не вводи SharedKernel и базовый ValueObject.
- При противоречии требований явно укажи его; не меняй контракт молча.
- Документация и подготовка репозитория сами по себе не разрешают писать
  приложение. Реализация начинается по отдельному указанию пользователя.
- Не добавляй намеренные дефекты в исходную версию ради будущего интервью.
- Не коммить, не публикуй и не создавай удалённый репозиторий без явного запроса.

## Проверка

Проверяй изменения соразмерно риску. Бизнес-правила покрывай тестами App,
SQLite и атомарность — Infra, HTTP-контракт — Api. Сверяй результат с
критериями приёмки. Не выдавай невыполненные проверки за пройденные.
